Layout and includes (mechanical)
--------------------------------
* Sources keep their Strikers file names. Includes "platform/sdk/net/X" became relative ("X", "online/X", "../X"), so net/ needs no include
  path of its own; tests include "../src/...". net/include/ holds np_glue.h and forwarding headers (vlink.h, np_online.h, np_online_api.h,
  np_net.h, np_signal.h, np_signal_http.h, np_http.h, np_json.h, np_app_version.h, np_keyboard.h, np_https.h, vlink_vita_radio.h) for
  Galaxy code (platform/src/mp/mp_service.cpp: np_https.h + np_json.h).
* Re-applying a Strikers sync: copy the files, run the include rewrite and the MSC_ -> SMG_ rewrite (both are plain text substitutions),
  then re-apply the hunks marked "Galaxy" (grep -rn Galaxy net/src net/tests).

Multi-peer (rooms of up to 4) and the star topology — online/np_online.*, np_signal.h, np_signal_http.cpp, np_signal_fake.cpp
------------------------------------------------------------------------------------------------------------------------------
* OnlineConfig::topology: TOPOLOGY_STAR (default) = the host peers with every guest, a guest only with the host; TOPOLOGY_MESH = Strikers.
  OnlineNet::TopologyPeer() decides; SyncMembers, RefreshCandidates, UpdatePhase, UpdateRelay (relay wanted only for topology peers),
  the relay-failed check and Started() consider topology peers only.
* Per-pair punch time and relay advice: SigMember::{pid, punchAtMs, steerRelay, steerReason}; the member's values win, SigRoom's are the
  fallback (two-player views, the fakes).
* ApplyRoom parses "members":[{slot,pid,name,vip,link,endpoint|null,punchAtMs,steer:{relay,reason}}] (at most 8 entries looked at; a bad,
  repeated or own slot is skipped; non-objects skipped); without members[] the legacy single "peer" is read as before. "slot" bounds
  0..3 (was 0..1). Server times for punchAtMs go through one helper (LocalTime) that rejects NaN / absurd values.
* PunchReport's peer slot goes to the service: {"result","path","ms","peer":n}.
* Per-member loss: OnlineConfig::onPeerLost(ctx, slot, why), once per lost connected path (Peer LOST/CLOSED, or a connected member that
  left the room view). onLost still means "no member connected" (a host losing one guest of three gets onPeerLost only).
  vlink_online.cpp forwards it to NpLanPeerLost.
* A member joining while others are connected: the same candidates are posted again (no new STUN: a new public port would make the
  connected members punch afresh).

Host migration (DESIGN.md section 8; coordinator request) — online/np_online.*, np_signal.h, np_signal_http.cpp, np_signal_fake.cpp
-----------------------------------------------------------------------------------------------------------------------------------
* SigRoom::hostSlot / hostEpoch from the room view ("host_slot"/"host_epoch" or the smg service's "hostSlot"/"hostEpoch"; absent = 0/0).
  The star is centred on the room's host: when it moves, the path to the old host is torn down (onPeerLost(old)), the new host begins
  paths to every guest, the guests to the new host (fresh hellos and keys; the service's per-pair punchAtMs applies).
* OnlineConfig::hostMigrationWaitMs (30 s): a console whose path to the host ended waits that long for a new host and a path to it while
  other members are in the room; only then onLost / OnLinkLost. OnlineInfo::{hostSlot, hostEpoch, migrating}.
* The memory fake moves the host to the lowest remaining slot on Leave and on SignalMemoryHubEvict (new: what the service does with a
  member that went silent).

Smaller changes
---------------
* The sceNet pool: one define NP_NET_POOL_BYTES = 2 MiB (vlink_vita_radio.h; -D can raise it) used by all four sceNetInit sites (ad hoc
  radio, Same Wi-Fi, online socket, HTTPS client); each logs its sceNetInit result and pool size. Strikers used 1 MiB at each site; Halo CE
  Vita found 1 MiB too small once sockets ask for larger buffers (SO_RCVBUF refused with ENOLIBMEM 0x804101C9, then ENOBUFS).
* Every setsockopt result is checked and logged (vlink_vita.cpp, vlink_udp.cpp, np_udp_vita.cpp, np_udp_posix.cpp, np_https_sys.cpp); a
  socket that cannot be made non-blocking is closed and not used. Nothing in net/ calls scePowerSetConfigurationMode.
* The keyboard: np_online_ime_vita.cpp takes the limit per request (NpOnlineImeOpenMax, up to 16 characters; Strikers fixed 10), and
  np_keyboard_vita.cpp passes the caller's maxChars. np_keyboard_host.cpp: SMG_KEYBOARD_TEXT / SMG_KEYBOARD_TEXT_FILE.
* Tests: online_test.cpp expects version 3.0.0 and X-Msc-Game, its HTTP test uses the built version and accepts a room that outlives its
  host; StubServer records request bodies; Console has topology / onPeerLost / migration-wait options. New: tests/online_star_test.inc
  (4-console star rig with a symmetric guest on the relay, guest drop + rejoin, host drop + migration, host leave, migration timeout,
  mesh, members[] parsing, the msc-online refusal, and the same star + migration against the service over HTTP when four accounts exist).
  run_online_tests.sh: paths for net/, M=-m64 default, CC/CXX overridable (GCC for ASan here). run_signal_http_test.sh registers 4 accounts.

Kept unchanged (Strikers 1.3 security fixes): turn_.Tick() before the signaling status check, the room key checks (no zero / short key),
XChaCha20-Poly1305 per-pair keys from both hellos, the 64-packet replay window, bounded JSON (12 levels, 4000 nodes), oversize-datagram
refusal, punch-report clamp. The 1.3 "NpNetLeave on failure" fix lived in np_menu_flow.cpp (not taken): Galaxy's session layer must call
NpLanRadioStop() / NpNetLeave() itself when NpLanRadioPoll returns -1 or the phase is FAILED (a failed session otherwise keeps its socket).

vitareview2 (9 Nov 2026): process-long sceNet stack, and the log in log.txt
--------------------------------------------------------------------------
* NP_NET_KEEP_STACK (vlink_vita_radio.h, default 1; -DNP_NET_KEEP_STACK=0 = Strikers): the ad hoc radio's cleanup no longer calls sceNetCtlTerm /
  sceNetTerm, frees the pool it gave sceNet, or unloads SCE_SYSMODULE_NET (it still ends the ad hoc layers, the socket, the worker and the
  dialog). np_https (g_netUp) and the online socket cache "the stack is up" and share it with the Same Wi-Fi path, which already never terminated it;
  after a Nearby session that had initialised the stack first they were left with a dead one (resolver / socket errors until a restart). A later
  session's sceNetInit answers EBUSY and frees its own spare pool (already handled). Hunks marked "Galaxy" / NP_NET_KEEP_STACK in vlink_vita_radio.cpp.
* np_log.h (new): NpLogf(tag, fmt, ...) = the old fprintf(stderr, "[tag] ...") plus, on the Vita, port_log_summary (the basic log, log.txt;
  weak, so a link without the port still works). VLV_LOG, VLINK_LOG, NPN_LOG, the radio's one-line events (sceNetInit, ad hoc id accepted /
  refused, NetCheck dialog, CommonDialog set-up, cell gone / peer seen), np_https_sys's Log, the https failure line and the keyboard failure
  now use it. Per-packet lines (vlink.cpp "rx" / "tx", SMG_LINK_TRACE) stay stderr-only (VLINK_TRACE). -DNP_LOG_STDERR_ONLY = Strikers.
  Volume: one line per event; the periodic per-member link statistics (SMG_NET_STATS_MS) and each https request line are the busiest.

strikerport (13 Nov 2026 night): Strikers fixes made after the vendoring (net/ from Strikers 1.3 at 92f5bc6f), ported and adapted
----------------------------------------------------------------------------------------------------------------------------------

  np_signal_http and, as ours, np_natpmp / np_upnp.

netport31 (17 Nov 2026): Strikers network fixes of 15-16 Nov, ported where Galaxy had the same bug
----------------------------------------------------------------------------------------------------
* heldpoll23 (c9e362b4): np_http.h HttpStart(..., ioTimeoutMs, ...) + HeldIoMs(hold) = hold + 10 s; np_signal_http.cpp StartJob passes it for a
  held room poll. Galaxy's service holds a room poll 25 s while the room forms and 55 s for a settled host (server rooms4.js pollPlan, 8 s
  busy); np_https ended every request after 10 s without a byte, so on the console every held poll failed, counted towards kPollGiveUp and
  the room was given up after about 4 minutes. Ordinary requests keep 10 s (np_https.cpp DefaultIoMs). The plain desktop client
  (np_http_plain.cpp) applies the same no-data limit now (default 10 s), so the host tests see the console's rule.
* Give-way (new, follows from the above): np_https runs ONE request at a time, so a menu's request (friends, times, invites) waited for a
  whole hold (up to 55 s). np_https_waiting(except) / NpNet::HttpOthersWaiting(handle): the held poll is given up when another request
  waits and asked again at once behind it (the existing svcfix2 path that already did this for the signaling's own queue).
* onmatch23 (735f4f4a): a "Content-Type: x" header line is taken as the request's content type instead of refusing the request (no Galaxy
  caller sends one today; the plain clients accepted it, the console did not). PUT and DELETE were already sent correctly in Galaxy.
  One service address for the sign-in and the rooms was already the case (mp_svc_signin_poll hands ServiceUrl() to NpNetConfigureService);
  tests/mp/service_test.cpp now checks it.
* onmatch23 (uncommitted, finished here): the socket budget. np_https_sys counts every socket and epoll id per pool (HTTPS, UPnP), refuses a

  cancel path of np_https, np_https_sys (Vita and POSIX), np_http_plain, np_upnp closes its socket; no leak found. The plain client now closes
  the socket of a request given up (HttpCancel) within 50 ms instead of keeping it until its own time limit.
* onlogin23 (15b8b1a1): NOT ported, Galaxy has no SO layer and opens no link before a session (tests/mp/online_nolink_test.cpp proves the

mpwifi44 (22 Nov 2026): the reason of a link that did not come up
-----------------------------------------------------------------
The owner's console (build console27) answered "Couldn't connect to Wi-Fi. Check your Wi-Fi settings." to Play Together while it was on Wi-Fi and
the connection check passed. NpLanRadioPoll's -1 carried no reason, so the game showed the Wi-Fi sentence for every one of them.
* np_glue.h NpLanRadioFailKind(const char** why): why the last NpLanRadioPoll answered -1. 1 = the console is not connected to an access point or
  has no address (sceNetCtlInetGetState read and not CONNECTED, no IP): the only case the player is told to check the Wi-Fi settings; 2 = anything
  else (the NET module, sceNetInit, sceNetCtlInit, a refused sceNetCtlInetGetState, the socket, SO_NBIO, the bind, an online session that failed,
  online chosen without a session); 0 = not known (Nearby keeps its own lines). vlink_vita.cpp WifiOpen sets it at every `return false`, with the
  SCE code, and logs "Same Wi-Fi could not open: <why>" (three of those returns logged nothing before). np_glue.cpp (desktop): 2 for its UDP link.
* vlink_vita.cpp WifiOpen, the bind. The console's log (console27, an iPhone hotspot, the first Play Together after boot, nothing online run yet):
  "sceNetInit (Same Wi-Fi, pool 2048 KiB): 0x00000000", "bind to UDP port 41100 failed", every time, with no code. WHY the Vita refuses that
  bind is not known yet (nothing of the game holds the port: the only other binds are the online / by-address socket, which was not open). The
  online socket already walks eight ports for the same symptom (np_net.h kPortTries, C3). Same Wi-Fi does the same now: the configured port,
  then the next seven; g_wifi.port is the one that bound (back to the configured one at close). Discovery still works across the range: the
  subnet broadcast goes to all eight ports (answers are unicast to the asker's port), 255.255.255.255 to the first. Every step is logged:
  sceNetSocket's result with the address and netmask, each refused bind with its code, the socket id, SO_BROADCAST's result and sin_len, and the
  port finally used. No SO_REUSEADDR: if the system or a plug-in owns 41100, sharing it would hand it our datagrams. The desktop UDP backend
  (vlink_udp.cpp, the Mac bot, emulators) still uses one port: a console on 41101+ reaches it with its probes, not by the bot's broadcasts.
The game side (platform/src/mp): mp_netglue.cpp mp_net_link_fail, mp_transport_vlink.cpp (MP_ERR_INTERNAL instead of MP_ERR_NO_WIFI for kind 2),
mp_core.cpp scanError / scanRetry, mp_gather.cpp (a failed start no longer stays; gathering without the local link). Not compiled into a VPK or
run on a console by the author: syntax-checked with arm-vita-eabi-g++ only. Tests: tests/mp/gather_wifi_test.cpp (the hook scripted).
